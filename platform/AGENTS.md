# Platform Gateway (ASP.NET Core 10, `:8080`)

Area-specific guidance. Cross-service contracts (SSE formats, ApiError, backend trust boundary, 202 flow, auth) live as invariants in the repo-root [AGENTS.md](../AGENTS.md) with full detail in [docs/cross-service-contracts.md](../docs/cross-service-contracts.md) — read those first when changing anything another service consumes.

## Layout

Solution `Platform.sln`, dependencies one-way `Web -> Service` (no data layer):

- `src/Platform.Service` — business logic: the shared chat pipeline agents (`ChatService` thin transport shell — escalates `PersistFailure` on the blocking path only — plus `SkillRoutingAgent`, `ChatContextProvider`, `ChatTurnRecorder`; wrapping order and roles are pinned in the Gotchas below), `PromptComposition`/`PromptCompositionResolver` (see the P1 gotcha), identity/memory-key derivation (`IChatIdentityAccessor`/`ChatMemoryKeyDerivation`), the mem0 clients, and the proxy clients (`BackendClient`, `SkillService`, `WorkflowEngineClient`, `AgentService` — passes ETag/If-Match verbatim, 5xx → 502), DTOs. The provider/recorder boundary, not a specific `IMem0Client` implementation, owns mem0 best-effort degradation.
- `src/Platform.Web` — controllers, public-key-only ES256 JWT validation (tokens are issued by backend), SSE streaming, AG-UI endpoint wiring, `GlobalExceptionHandler`, executable app. `Infrastructure/` holds the AG-UI/JWT/identity adapters (`AguiWireDedupAgent`, `JwtTenantIsolationKeyProvider`, `HttpChatIdentityAccessor`, `AgentFrameworkLlmAgent`) — their behavior contracts live in the Gotchas below.
- `tests/Platform.Service.Tests` + `tests/Platform.Web.Tests` — xUnit, hand-written fakes (no mocking library).

## Commands (run from `platform/`)

```bash
dotnet build
dotnet test
dotnet test tests/Platform.Service.Tests
dotnet run --project src/Platform.Web
```

After changing `Platform.Service`, rebuild the solution before running only `Platform.Web`; the .NET runtime handles transitive dependencies automatically (no stale-artifact issue like Maven's SNAPSHOT).

## Gotchas

- **Workflow admin controller base** (`WorkflowAdminControllerBase`): `/api/admin/workflows*` and `/api/admin/orchestrators*` derive from `WorkflowAdminControllerBase` which declares `[ApiController]` and `[Authorize(Policy = "workflow.manage")]` at the base class level. Individual routes and actions remain in the derived controllers — never redeclare authorization or the controller attribute.
- **Authenticated chat transport (P4-1 PARTIAL)** (`ChatController`): `POST /api/chat`, `POST /api/chat/stream`, `GET /api/chat/history`, and `GET /api/chat/history/page` require JWT. Requests no longer accept `userId`; `conversationId` is optional, and missing/blank input is canonicalized to a Platform-generated UUID returned by both POST endpoints as `X-Conversation-Id` (`turnId` is still pending). Blocking chat completes before returning; streaming writes and flushes SSE `data:` lines (no space after colon). Mid-stream failures write `event:error\ndata:<fixed Chinese error message>\n\n` and end normally; client cancellations do not write an error frame.
- **Agent Framework API traps:** the extension is `GetChatClient(model).AsAIAgent(...)` — the *string* overload carries instructions (`ChatClientAgentOptions` has NO `Instructions` property). `Microsoft.Extensions.AI.ChatMessage` collides with `OpenAI.Chat` — alias it. `ILlmAgent` no longer has a `tools` parameter (native function-calling dead code removed; `LlmTool` is only used in `SkillRoutingAgent` for deterministic skill routing).
- **AG-UI endpoint:** `Microsoft.Agents.AI.Hosting.AGUI.AspNetCore` (preview, restores against stable `Microsoft.Agents.AI`) + `AddAGUI()` in `Program.cs`. The hosted agent is registered via the **DI-overload** `builder.Services.AddAIAgent("OperationsAssistant", factory, ServiceLifetime.Singleton).WithInMemorySessionStore(withIsolation: true)` — not a bare `AsAIAgent()` — because only that overload wires a session store + `AIContextProviders`; then `app.MapAGUI(copilotAgent, "/api/copilot/agui").RequireAuthorization()`. No JWT or invalid JWT → `401`; a token lacking nonblank tenant or user claims must fail closed in `JwtTenantIsolationKeyProvider`, never create a partial/shared key. MapAGUI emits standard `data: ` (with space) — different from ChatController's hand-rolled `data:` on purpose.
- **Two named hosted agents, both `Singleton`:** `"OperationsAssistant"` (AG-UI, pipeline outer→inner `AguiWireDedupAgent → ChatTurnRecorder → SkillRoutingAgent → ChatClientAgent`, `ChatClientAgent` carries `copilotInstructions`) and `"ChatAssistant"` (`ChatService`'s pipeline `ChatTurnRecorder → SkillRoutingAgent → ChatClientAgent`, no `copilotInstructions`, no dedup layer — `ChatService` only ever sends the new turn, never AG-UI's resent full array; manually assembled into an `AIHostAgent` since `AddAIAgent` only registers keyed `AIAgent`/`AgentSessionStore`, not an `AIHostAgent`). Both share one `InMemoryChatHistoryProvider` singleton (stateless config object; the actual window lives in `AgentSession.StateBag`). In both pipelines `ChatTurnRecorder` wraps `SkillRoutingAgent` so a routed/short-circuited turn is still recorded.
- **Singleton lifetime trap:** `MapAGUI` resolves its agent from the *root* provider at startup (decompiled proof) — declaring either hosted agent `Scoped` makes `dotnet run` crash on boot in `Development` (`ValidateScopes=true`). Per-request identity therefore cannot ride the agent's own lifetime: `ChatContextProvider`/`ChatTurnRecorder`/`SkillRoutingAgent` hold only `IServiceScopeFactory` and open a fresh scope per call to resolve `IMem0Client`/`IConversationStore`/`IChatIdentityAccessor`/`IWorkflowEngineClient` — never captured at construction (avoids a captive dependency on the Singleton hosted agents; `IChatIdentityAccessor` itself rides `IHttpContextAccessor`'s `AsyncLocal`, so per-request identity still resolves correctly even though the agent instance is shared).
- **Short-term memory / session store:** the self-written `InMemoryChatMemoryStore`/`IChatMemoryStore` are gone, replaced by the framework session store above. `SlidingWindowCompactionStrategy(CompactionTriggers.MessagesExceed(20), minimumPreservedTurns: 1)` trims at turn granularity, so a `FunctionCallContent`/`FunctionResultContent` pair is never split (the old `RemoveAt(0)` could split one). Isolation: AG-UI's store is `withIsolation:true` keyed on nonblank `{tenant}:{user}` from the JWT (`JwtTenantIsolationKeyProvider`, fail-closed — `Strict=true` throws if either identity claim is missing); pending P4-3, `ChatAssistant` remains `withIsolation:false` and `ChatMemoryKeyDerivation` prefixes its canonical conversation UUID with authenticated `{tenant}:{user}`. The store is per-process and non-durable by design: restarting Platform drops every short-term window (durable history stays in backend appdb, so only in-conversation context is lost, and multi-instance deployments do not share windows). Making it survive restarts means swapping the session store for a durable one (`WithSessionStore(...)`), not adding a table alongside it — do not treat the in-memory store as a bug to patch around.
- **Trusted proxy + rate limiting:** full-container nginx and platform share the isolated `frontend_platform_proxy` Compose network (`TRUSTED_PROXY_CIDR`, default `10.253.254.0/28`). Platform trusts forwarded headers only from that CIDR; it must never be changed to the shared default network. Host mode leaves the setting absent and ignores caller-supplied forwarding headers. LLM endpoints (`/api/chat`, `/api/chat/stream`, `/api/copilot/agui` — all authenticated since P4-1) are limited to 30 requests/minute/client IP and 429 responses use the standard `ApiError` shape.
- **mem0 (`Mem0Client`):** authenticated `ChatContextProvider` calls `recall` before the LLM and injects memories into `AIContext.Instructions` (not `Messages` — messages get persisted into chat history and would re-accumulate every turn); authenticated `ChatTurnRecorder` calls `remember` after a complete turn. Both hosted agents share this authenticated path, so mem0 also covers the AG-UI copilot. `ChatContextProvider`/`ChatTurnRecorder` enforce best-effort around every `IMem0Client` call: errors are logged and degrade to empty recall/no-op remember even if an alternate implementation throws.
- **Correlation ID tracking:** Platform derives correlationId from `HttpContext.TraceIdentifier` (never trusts inbound headers). Outbound calls forward via `CorrelationIdForwardingHandler` in `X-Correlation-Id` header. Error responses return ID in response header. See [docs/cross-service-contracts.md § Error shape & correlation](../docs/cross-service-contracts.md#error-shape--correlation) for full chain.
- **Observability:** both blocking and streaming endpoints emit a business `Activity` span; .NET → OpenTelemetry → OTLP → Langfuse (production) or Console + ring-buffer (lite mode). Actual wiring happens in `Program.cs` reading env `LANGFUSE_OTEL_ENDPOINT` and `LANGFUSE_OTEL_AUTH` for OTLP, or `OTEL_MODE=console` for console exporter + `RingBufferActivityExporter` (bounded queue, last 200 spans, readable via `get_recent_traces` AIFunction); no `OpenTelemetry` config section in appsettings.json — it's all env-driven. LiteLLM's `success_callback` covers token/cost as the second observability path. All 5xx errors return a fixed generic Chinese message to the client (details only in app logs), no exception details exposed.
- **Health endpoints:** `GET /actuator/health` (AllowAnonymous) is a liveness alias that always returns `{status:"UP", ready:true}` — used by the Vite dev proxy check and kept for backward compatibility. `GET /actuator/health/ready` (AllowAnonymous) is the readiness endpoint `infra/docker-compose.yml`'s platform healthcheck actually calls: it runs six dependency checks (`backend`, `workflow`, `rabbitmq` required; `litellm`, `mem0`, `telemetry` optional/best-effort) with a 2-second result cache and a 1-second per-check timeout, returning `200` with `ready:true` when all required checks pass (optional-check failures degrade the reported status to `DEGRADED` but do not flip `ready`) or `503` with `ready:false` otherwise. `GET /actuator/health/live` is the same liveness alias under its own explicit path.
- **Skill/Business Workflow proxy routing:** `WorkflowEngineClient` is the client for the whole Python workflow engine (skills, Business Rules, nodes, and tools). An **Agent Skill** is a `SKILL.md` package; a **Business Workflow** is declarative YAML. During P2–P5, `SkillController` keeps the legacy full-function dual-track surface while `BusinessWorkflowController` proxies `/api/business-workflows*` CRUD/export to Backend and flow validation to workflow's `/business-workflows/validate`; old `/skills/validate` remains only as its compatibility alias. Both kinds retain unified `POST /api/skills/{name}/invoke`, so `SkillRoutingAgent` remains kind-agnostic. `NodeController` and `ToolController` proxy their safe catalogs. Platform preserves backend/workflow `kind` and `bindable` exactly; it never YAML-sniffs, infers binding eligibility, or changes revision semantics. P5 must not remove flow actions or expose an Agent-Skill-only Skill surface until C8 records flow-write usage `= 0`, dual-track traffic cutover, and a completed rollback window.
- **P3-R2 compatibility evidence:** Platform counts outer public validation once, replaces invoke origin with server-derived value (`public_skills` or `workflow_unified_invoke`), marks downstream as `dependency`. See [docs/cross-service-contracts.md § P3-R2](../docs/cross-service-contracts.md#p3-r2-compatibility-evidence) and [runtime evidence contract](../plans/architecture-hard-reset/09-p3-r2-runtime-evidence-contract.md).
- **Agent Registry proxy** (`/api/agents*`): `AGENT_BUILDER_ENABLED` (default false; when off, entire endpoint family returns 404 fail-closed before auth check). When enabled, the whole endpoint family is an ADMIN-only Builder API at both platform and backend; its detail contains the authoring draft, so USER catalog/discovery must use a future separate redacted contract rather than reusing it. `AgentService` forwards identity headers + `X-Internal-Token` to backend; `X-User-Capabilities` is sent only when the signed JWT `capabilities` claim is nonblank. Draft update and validate require `If-Match` (missing → 428, stale → 409); platform transparently forwards status/body/ETag. `GET /api/features` (AllowAnonymous) returns `{agentBuilderEnabled, agentTestRunEnabled, workflowDesignerEnabled, multiAgentDispatchEnabled, contextEnrichmentEnabled, agentChatEnabled, agentWriteToolsEnabled, agentTriggersEnabled}` in camelCase; `multiAgentDispatchEnabled` is independently fail-closed (no longer pre-multiplied by designer), while `agentTestRunEnabled` is false unless `AGENT_BUILDER_ENABLED` is also on.
- **O5 trigger proxy** (`/api/admin/triggers*`): `AGENT_TRIGGERS_ENABLED` (default false; when off, entire endpoint family returns 404 fail-closed before auth check). When enabled, `/api/admin/triggers` (CRUD), `/api/admin/triggers/{id}` (retrieve/cancel), and `/api/admin/triggers/{id}/occurrences` (fire history) require `workflow.manage` authorization. Platform transparently forwards identity headers + `X-Internal-Token` to backend and returns status/body/ETag.
- **D4 Workflow Designer proxy:** `/api/admin/workflows*` and `/api/admin/orchestrators*` are gated by `WORKFLOW_DESIGNER_ENABLED` before authentication and require the exact `workflow.manage` capability when enabled; ADMIN alone never grants access. Platform transparently forwards identity/capability, JSON, `If-Match`, ETag and downstream 2xx/4xx while mapping transport/5xx failures to the controlled gateway error contract.
- **D5 Root dispatch:** `POST /api/admin/orchestrators/{id}/runs` is Backend-durable allocation first. Platform then best-effort posts only `{command_id, context:{}}` to Workflow's internal `/orchestrator-runs/{run}/dispatch`; Workflow claims, renews, ACKs, and terminal-transitions the root itself. Platform must never claim the root command or send a decoded snapshot. Public `Context` on the start body is deliberately ignored: Backend hashes only server-owned `root_input {message, observed_at}`, and Workflow acquires any read-only context through Backend's authority-checked route. A failed Workflow kick leaves the Backend command reclaimable.
- **D6 chat canary (removal pending P4-2):** `AGENT_CHAT_ENABLED` and the server-only comma-separated `AGENT_CHAT_TENANT_ALLOWLIST` jointly opt authenticated tenants into Root Orchestrator chat; non-allowlisted authenticated callers stay byte-for-byte on legacy, while unauthenticated chat is rejected by the P4-1 JWT boundary. Both `/api/chat*` and AG-UI place the same `AgentChatRoutingAgent` inside `ChatTurnRecorder`, preserving transport/session wrappers and exactly-once complete-turn persistence/mem0 remember. Backend `/api/runtime-discovery/resolve` is the selection/authorization authority: an omitted Orchestrator may resolve to `legacy`, but an explicit invalid/cross-tenant/disabled/unpublished Orchestrator must surface 404/409 and never fall back. Backend durably accepts `/api/chat-runs` before Platform best-effort kicks Workflow; client disconnect detaches from polling and does not cancel the durable run. `waiting_input` returns the first server-bounded clarification; the next turn finds the unique owner-scoped active root by conversation and resumes that immutable run. An explicit Orchestrator switch first durably cancels the prior active root. Explicit Orchestrator chat session keys include its ID so A/B histories do not mix. Turning off the flag is the rollback and leaves the legacy session namespace intact.
- **D7 approvals and operations:** `AGENT_WRITE_TOOLS_ENABLED` defaults false and returns 404 before public approval/operations use. `RunApprovalController` is authenticated but deliberately is not ADMIN- or `workflow.manage`-gated: the Backend is the decision authority and verifies tenant, required role, expiry, exact pending action/checkpoint, replay, and separation of duties. Decision calls require a caller-supplied `Idempotency-Key`; Platform forwards it unchanged and only best-effort kicks Workflow after a durable approval. `/api/admin/operations/*` is a redacted `workflow.manage` proxy for regression gate recording/override, future-root rollout, metrics, version comparison, and legacy inventory; it never exposes prompts, tool values, tokens, context, or idempotency keys. `metrics` and `version-comparison` pass an optional `window_days` query parameter through verbatim (W2-02(e)) and deliberately validate nothing — Backend owns the 1–365 bound and the default 90, so platform must never grow a second copy of those numbers. A rollout changes only future root selection, never an active snapshot.
- **D3 capability and group forwarding:** preserves JWT claims via `X-User-Capabilities` and `X-User-Groups`; malformed claims fail closed. Platform never derives from ADMIN, never accepts lists from public bodies. See [docs/agent-platform-contracts.md § Direct Agent runtime](../docs/agent-platform-contracts.md#direct-agent-runtime-d3-all-four-services).
- **P1 prompt composition (`PromptComposition` + `PromptCompositionResolver`):** one deterministic assembler shared by both chat chains; constants are default source. `PROMPT_ARTIFACTS_ENABLED` (default false) is structural: off = resolver not registered, constants only (pinned by goldens). On = tenant canary via backend config key `prompt.manifest_revision`, manifest from `GET /api/prompt-manifests/{revision}/resolved` (never proxied). Failures → constants + logging (availability wins). `PROMPT_ARTIFACTS_SHADOW` observe-only. Four shared slots identity across `/api/chat*`/AG-UI; persona per-transport. See [docs/cross-service-contracts.md § Prompt manifest](../docs/cross-service-contracts.md#prompt-manifest-p1).
- **E1/E3 Context Enrichment:** routes gated fail-closed: both `MULTI_AGENT_DISPATCH_ENABLED` and `CONTEXT_ENRICHMENT_ENABLED` required. See [docs/context-enrichment-contracts.md](../docs/context-enrichment-contracts.md).
- **JWT verification and rotation:** ring maps `kid` → P-256 public PEM (capped 8 keys); validation requires exact `iss`/`aud`/`kid` match. Unknown kids fail closed. See [docs/cross-service-contracts.md § Auth](../docs/cross-service-contracts.md#auth) for rotation procedure.
- **Authentication edge limits:** login/register bodies are capped at 16 KiB before MVC/backend work. The fixed-window limiter is deliberately per process instance: 20 auth requests/minute per client IP, then 5 login attempts/minute per normalized username or 3 registrations/minute per normalized tenant+username. Its bounded 8,192-partition tables fail closed when full and do not merge hash collisions. Forwarded client IP is trusted only from `TRUSTED_PROXY_CIDR`; middleware ordering keeps the IP gate and body cap ahead of account hashing. Distributed/global throttling remains an ingress concern.
- **Credential startup gate:** outside `Development`, startup rejects blank or committed-development values for the internal token, RabbitMQ credentials, issuer/audience, or JWT public ring. Local helpers explicitly set Development; do not weaken validation to make raw production-mode Compose accept development credentials.
- **Env:** `LLM_BASE_URL` (default `http://localhost:4000`), `LITELLM_KEY` (LiteLLM virtual key, default `sk-1234`), `CHAT_MODEL` (default `gpt-4o-mini`; `mock-gpt` for keyless testing), `WORKFLOW_BASE_URL` (e.g. `http://localhost:8001`, used for skill invoke/validate/catalog and node catalog), `BACKEND_BASE_URL`, `RABBITMQ_URL`, `INTERNAL_API_TOKEN`, `JWT_ISSUER`, `JWT_AUDIENCE`, `JWT_PUBLIC_KEY_RING_JSON`, `TRUSTED_PROXY_CIDR`, `LANGFUSE_OTEL_ENDPOINT`, `LANGFUSE_OTEL_AUTH`, `AGENT_BUILDER_ENABLED`, `AGENT_TEST_RUN_ENABLED`, `WORKFLOW_DESIGNER_ENABLED`, `MULTI_AGENT_DISPATCH_ENABLED`, `CONTEXT_ENRICHMENT_ENABLED`, `AGENT_CHAT_ENABLED`, `AGENT_CHAT_TENANT_ALLOWLIST`, `AGENT_TRIGGERS_ENABLED`, `PROMPT_ARTIFACTS_ENABLED`, `PROMPT_ARTIFACTS_SHADOW` (feature flags default false; E1/E3 context enrichment requires both `MULTI_AGENT_DISPATCH_ENABLED=true` and `CONTEXT_ENRICHMENT_ENABLED=true`; chat requires both its flag and exact server allowlist membership). **Lite-only:** `MEM0_MODE` (unset = HTTP client, `inmemory` = in-memory per-user recall/remember), `OTEL_MODE` (unset = OTLP to Langfuse, `console` = console exporter + ring-buffer, exposes `get_recent_traces` AIFunction to chat).

## Testing

Prefer focused tests near the changed layer: service units in `Service.Tests` (fake `HttpMessageHandler` for BackendClient), controller/application tests in `Web.Tests` (`WebApplicationFactory`). Hand-written fakes only — no mocking library.
