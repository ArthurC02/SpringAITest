# Platform Gateway (ASP.NET Core 10, `:8080`)

Area-specific guidance. Cross-service contracts (SSE formats, ApiError, backend trust boundary, 202 flow, auth) live in the repo-root [AGENTS.md](../AGENTS.md) — read that first when changing anything another service consumes.

## Layout

Solution `Platform.sln`, dependencies one-way `Web -> Service` (no data layer):

- `src/Platform.Service` — business logic: `ChatService` (thin transport shell over the shared Agent Framework pipeline — derive session key, `AIHostAgent.RunAsync`/`RunStreamingAsync`, save session, escalate `PersistFailure` on the blocking path only), `SkillRoutingAgent` (deterministic skill-routing `DelegatingAIAgent` middleware, shared by both chat pipelines), `ChatContextProvider` (`AIContextProvider`: numeric guardrail prompt + authenticated mem0 recall, injected as `Instructions`, never into history), `ChatTurnRecorder` (`DelegatingAIAgent`: authenticated mem0 remember + conversation persistence, wraps `SkillRoutingAgent` so a routed/short-circuited turn is still recorded), `Mem0Client` / `InMemoryMem0Client` (per-userId in-memory recall/remember, lite-only), `IChatIdentityAccessor`/`ChatMemoryKeyDerivation` (per-request login identity + mem0/session key derivation), `BackendClient` proxy to backend `:8002`, `SkillService` (proxies CRUD to backend, invoke/validate/catalog to workflow), `AgentService` (transparent proxy to backend `/api/agents*`, forwards identity + capabilities headers, passes ETag/If-Match verbatim, 5xx → 502), `RingBufferActivityExporter` (OTel ring-buffer for console mode, lite-only), DTOs. The provider/recorder boundary, not a specific `IMem0Client` implementation, owns mem0 best-effort degradation.
- `src/Platform.Web` — controllers (`ChatController`, `SkillController` for CRUD, `NodeController`/`ToolController` for safe registry catalogs, `AgentController` for registry proxy), JWT validation (tokens are *issued* by backend, same `JWT_SECRET`), SSE streaming, AG-UI endpoint wiring, `GlobalExceptionHandler`, executable app. `Infrastructure/`: `AguiWireDedupAgent` (dedupes AG-UI's per-turn resent full message array by ID, with conservative assistant role/content/tool-call fingerprint fallback when client IDs are rebuilt), `JwtTenantIsolationKeyProvider` (AG-UI `{tenant}:{user}` session isolation key from nonblank JWT claims), `HttpChatIdentityAccessor` (implements `IChatIdentityAccessor` off `IHttpContextAccessor`), `AgentFrameworkLlmAgent` (implements `ILlmAgent`).
- `tests/Platform.Service.Tests` + `tests/Platform.Web.Tests` — xUnit, 531 tests total (Service 300 + Web 231), hand-written fakes (no mocking library).

## Commands (run from `platform/`)

```bash
dotnet build
dotnet test
dotnet test tests/Platform.Service.Tests
dotnet run --project src/Platform.Web
```

After changing `Platform.Service`, rebuild the solution before running only `Platform.Web`; the .NET runtime handles transitive dependencies automatically (no stale-artifact issue like Maven's SNAPSHOT).

## Gotchas

- **Streaming vs blocking** (`ChatController`): `POST /api/chat` is synchronous and completes before returning; `POST /api/chat/stream` returns an `IAsyncEnumerable<string>`, writing chunks as SSE `data:` lines (no space after colon) and flushing after each write. Mid-stream failures are caught with try/catch: on exception, platform writes `event:error\ndata:<fixed Chinese error message>\n\n` then ends the response normally (preserves already-sent tokens and graceful close). Client cancellations (`OperationCanceledException`) do not write an error frame.
- **Agent Framework API traps:** the extension is `GetChatClient(model).AsAIAgent(...)` — the *string* overload carries instructions (`ChatClientAgentOptions` has NO `Instructions` property). `Microsoft.Extensions.AI.ChatMessage` collides with `OpenAI.Chat` — alias it. `ILlmAgent` no longer has a `tools` parameter (native function-calling dead code removed; `LlmTool` is only used in `SkillRoutingAgent` for deterministic skill routing).
- **AG-UI endpoint:** `Microsoft.Agents.AI.Hosting.AGUI.AspNetCore` (preview, restores against stable `Microsoft.Agents.AI`) + `AddAGUI()` in `Program.cs`. The hosted agent is registered via the **DI-overload** `builder.Services.AddAIAgent("OperationsAssistant", factory, ServiceLifetime.Singleton).WithInMemorySessionStore(withIsolation: true)` — not a bare `AsAIAgent()` — because only that overload wires a session store + `AIContextProviders`; then `app.MapAGUI(copilotAgent, "/api/copilot/agui").RequireAuthorization()`. No JWT or invalid JWT → `401`; a token lacking nonblank tenant or user claims must fail closed in `JwtTenantIsolationKeyProvider`, never create a partial/shared key. MapAGUI emits standard `data: ` (with space) — different from ChatController's hand-rolled `data:` on purpose.
- **Two named hosted agents, both `Singleton`:** `"OperationsAssistant"` (AG-UI, pipeline outer→inner `AguiWireDedupAgent → ChatTurnRecorder → SkillRoutingAgent → ChatClientAgent`, `ChatClientAgent` carries `copilotInstructions`) and `"ChatAssistant"` (`ChatService`'s pipeline `ChatTurnRecorder → SkillRoutingAgent → ChatClientAgent`, no `copilotInstructions`, no dedup layer — `ChatService` only ever sends the new turn, never AG-UI's resent full array; manually assembled into an `AIHostAgent` since `AddAIAgent` only registers keyed `AIAgent`/`AgentSessionStore`, not an `AIHostAgent`). Both share one `InMemoryChatHistoryProvider` singleton (stateless config object; the actual window lives in `AgentSession.StateBag`).
- **Singleton lifetime trap:** `MapAGUI` resolves its agent from the *root* provider at startup (decompiled proof) — declaring either hosted agent `Scoped` makes `dotnet run` crash on boot in `Development` (`ValidateScopes=true`). Per-request identity therefore cannot ride the agent's own lifetime: `ChatContextProvider`/`ChatTurnRecorder`/`SkillRoutingAgent` hold only `IServiceScopeFactory` and open a fresh scope per call to resolve `IMem0Client`/`IConversationStore`/`IChatIdentityAccessor`/`IWorkflowService` — never captured at construction (avoids a captive dependency on the Singleton hosted agents; `IChatIdentityAccessor` itself rides `IHttpContextAccessor`'s `AsyncLocal`, so per-request identity still resolves correctly even though the agent instance is shared).
- **Short-term memory / session store:** the self-written `InMemoryChatMemoryStore`/`IChatMemoryStore` are gone, replaced by the framework session store above. `SlidingWindowCompactionStrategy(CompactionTriggers.MessagesExceed(20), minimumPreservedTurns: 1)` trims at turn granularity, so a `FunctionCallContent`/`FunctionResultContent` pair is never split (the old `RemoveAt(0)` could split one). Isolation: AG-UI's store is `withIsolation:true` keyed on nonblank `{tenant}:{user}` from the JWT (`JwtTenantIsolationKeyProvider`, fail-closed — `Strict=true` throws if either identity claim is missing); `ChatAssistant`'s store is `withIsolation:false` because `ChatService`'s logged-in `conversationId` is already prefixed `{tenant}:{user}` by `ChatMemoryKeyDerivation`, deliberately preserving anonymous-chat continuity.
- **Trusted proxy + rate limiting:** full-container nginx and platform share the isolated `frontend_platform_proxy` Compose network (`TRUSTED_PROXY_CIDR`, default `10.253.254.0/28`). Platform trusts forwarded headers only from that CIDR; it must never be changed to the shared default network. Host mode leaves the setting absent and ignores caller-supplied forwarding headers. Anonymous LLM endpoints are limited to 30 requests/minute/client IP and 429 responses use the standard `ApiError` shape.
- **mem0 (`Mem0Client`):** authenticated `ChatContextProvider` calls `recall` before the LLM and injects memories into `AIContext.Instructions` (not `Messages` — messages get persisted into chat history and would re-accumulate every turn); authenticated `ChatTurnRecorder` calls `remember` after a complete turn. Anonymous `/api/chat*` retains short-term session continuity but performs neither operation nor persistence. Both hosted agents share the authenticated path, so mem0 also covers the AG-UI copilot. `ChatContextProvider`/`ChatTurnRecorder` enforce best-effort around every `IMem0Client` call: errors are logged and degrade to empty recall/no-op remember even if an alternate implementation throws.
- **Observability:** both blocking and streaming endpoints emit a business `Activity` span; .NET → OpenTelemetry → OTLP → Langfuse (production) or Console + ring-buffer (lite mode). Actual wiring happens in `Program.cs` reading env `LANGFUSE_OTEL_ENDPOINT` and `LANGFUSE_OTEL_AUTH` for OTLP, or `OTEL_MODE=console` for console exporter + `RingBufferActivityExporter` (bounded queue, last 200 spans, readable via `get_recent_traces` AIFunction); no `OpenTelemetry` config section in appsettings.json — it's all env-driven. LiteLLM's `success_callback` covers token/cost as the second observability path. All 5xx errors return a fixed generic Chinese message to the client (details only in app logs), no exception details exposed.
- **Health endpoint:** `GET /actuator/health` (AllowAnonymous) returns `{status:"UP"}` — used by container healthchecks and Vite dev proxy checks.
- **Skill/registry proxy routing:** `SkillController` routes CRUD/export to backend and invoke/validate/catalog to workflow. `NodeController` proxies `GET /api/nodes`; `ToolController` proxies authenticated `GET /api/tools` and returns Workflow Tool Registry's safe picker metadata (`name/kind/description/risk/returns`, never endpoint/token/implementation). Skill catalog includes workflow-owned `bindable`; Platform transparently preserves it and never infers binding eligibility from a name/source. Workflow failures surface as controlled errors; unreachable catalog/invoke → `502`.
- **Agent Registry proxy** (`/api/agents*`): `AGENT_BUILDER_ENABLED` (default false; when off, entire endpoint family returns 404 fail-closed before auth check). When enabled, the whole endpoint family is an ADMIN-only Builder API at both platform and backend; its detail contains the authoring draft, so USER catalog/discovery must use a future separate redacted contract rather than reusing it. `AgentService` forwards identity headers + `X-Internal-Token` to backend; `X-User-Capabilities` is sent only when the signed JWT `capabilities` claim is nonblank. Draft update and validate require `If-Match` (missing → 428, stale → 409); platform transparently forwards status/body/ETag. `GET /api/features` (AllowAnonymous) returns `{agentBuilderEnabled, agentTestRunEnabled, workflowDesignerEnabled}` in camelCase.
- **D4 Workflow Designer proxy:** `/api/admin/workflows*` and `/api/admin/orchestrators*` are gated by `WORKFLOW_DESIGNER_ENABLED` before authentication and require the exact `workflow.manage` capability when enabled; ADMIN alone never grants access. Platform transparently forwards identity/capability, JSON, `If-Match`, ETag and downstream 2xx/4xx while mapping transport/5xx failures to the controlled gateway error contract.
- **D5 Root dispatch:** `POST /api/admin/orchestrators/{id}/runs` is Backend-durable allocation first. Platform then best-effort posts only `{command_id, context:{}}` to Workflow's internal `/orchestrator-runs/{run}/dispatch`; Workflow claims, renews, ACKs, and terminal-transitions the root itself. Platform must never claim the root command or send a decoded snapshot. Public `Context` on the start body is deliberately ignored: Backend hashes only server-owned `root_input {message, observed_at}`, and Workflow acquires any read-only context through Backend's authority-checked route. A failed Workflow kick leaves the Backend command reclaimable.
- **D6 chat canary:** `AGENT_CHAT_ENABLED` and the server-only comma-separated `AGENT_CHAT_TENANT_ALLOWLIST` jointly opt authenticated tenants into Root Orchestrator chat; anonymous and non-allowlisted callers stay byte-for-byte on legacy. Both `/api/chat*` and AG-UI place the same `AgentChatRoutingAgent` inside `ChatTurnRecorder`, preserving transport/session wrappers and exactly-once complete-turn persistence/mem0 remember. Backend `/api/runtime-discovery/resolve` is the selection/authorization authority: an omitted Orchestrator may resolve to `legacy`, but an explicit invalid/cross-tenant/disabled/unpublished Orchestrator must surface 404/409 and never fall back. Backend durably accepts `/api/chat-runs` before Platform best-effort kicks Workflow; client disconnect detaches from polling and does not cancel the durable run. `waiting_input` returns the first server-bounded clarification; the next turn finds the unique owner-scoped active root by conversation and resumes that immutable run. An explicit Orchestrator switch first durably cancels the prior active root. Explicit Orchestrator chat session keys include its ID so A/B histories do not mix. Turning off the flag is the rollback and leaves the legacy session namespace intact.
- **D7 approvals and operations:** `AGENT_WRITE_TOOLS_ENABLED` defaults false and returns 404 before public approval/operations use. `RunApprovalController` is authenticated but deliberately is not ADMIN- or `workflow.manage`-gated: the Backend is the decision authority and verifies tenant, required role, expiry, exact pending action/checkpoint, replay, and separation of duties. Decision calls require a caller-supplied `Idempotency-Key`; Platform forwards it unchanged and only best-effort kicks Workflow after a durable approval. `/api/admin/operations/*` is a redacted `workflow.manage` proxy for regression gate recording/override, future-root rollout, metrics, version comparison, and legacy inventory; it never exposes prompts, tool values, tokens, context, or idempotency keys. A rollout changes only future root selection, never an active snapshot.
- **D3 capability and group forwarding:** Agent test runs preserve persisted JWT capability claims through `UserContext` and `X-User-Capabilities`. Repeated canonical `groups` claims are parsed as one bounded atomic set and regenerated as `X-User-Groups`; any malformed claim discards the whole group set. Runtime grant contract v1 uses `tool.use:<toolName>` and `knowledge.read:<canonical-lowercase-document-UUID>`; Platform never derives grants or groups from ADMIN and never accepts either list from public run bodies.
- **Env:** `LLM_BASE_URL` (default `http://localhost:4000`), `CHAT_MODEL` (default `gpt-4o-mini`; `mock-gpt` for keyless testing), `WORKFLOW_BASE_URL` (e.g. `http://localhost:8001`, used for skill invoke/validate/catalog and node catalog), `BACKEND_BASE_URL`, `RABBITMQ_URL`, `INTERNAL_API_TOKEN`, `JWT_SECRET`, `LANGFUSE_OTEL_ENDPOINT`, `LANGFUSE_OTEL_AUTH`, `AGENT_BUILDER_ENABLED`, `AGENT_TEST_RUN_ENABLED`, `WORKFLOW_DESIGNER_ENABLED`, `AGENT_CHAT_ENABLED`, `AGENT_CHAT_TENANT_ALLOWLIST` (feature flags default false; chat requires both its flag and exact server allowlist membership). **Lite-only:** `MEM0_MODE` (unset = HTTP client, `inmemory` = in-memory per-user recall/remember), `OTEL_MODE` (unset = OTLP to Langfuse, `console` = console exporter + ring-buffer, exposes `get_recent_traces` AIFunction to chat).

## Testing

Prefer focused tests near the changed layer: service units in `Service.Tests` (fake `HttpMessageHandler` for BackendClient), controller/application tests in `Web.Tests` (`WebApplicationFactory`). Hand-written fakes only — no mocking library.
