# Backend Core Service (ASP.NET Core 10, `:8002`)

Area-specific guidance. Cross-service contracts (X-Internal-Token + identity headers, 202 flow, auth/JWT, ApiError) live as invariants in the repo-root [AGENTS.md](../AGENTS.md) with full detail in [docs/cross-service-contracts.md](../docs/cross-service-contracts.md) — read those first when changing anything platform or workflow consumes.

## Layout

Solution `Backend.sln`, single project `src/Backend.Api` organized by feature folders (one per domain) with no layered dependencies. Data access is Dapper 2.x + Npgsql 9.x directly against appdb (PostgreSQL with pgvector), no ORM; in lite mode can switch to in-memory repositories (singleton per-request snapshots, no persistence across restarts). `Common/ApiErrors.cs` is the centralized 404 message factory for consistency across endpoints. Tests in `tests/Backend.Api.Tests` (xUnit; all PostgreSQL-dependent tests run with tenant prefixing and IAsyncLifetime cleanup; hand-written fakes, in-memory fixtures).

## Commands (run from `backend/`)

```bash
dotnet build
dotnet test
dotnet run --project src/Backend.Api
```

Requires appdb running (default `DB_CONNECTION_STRING`: `Host=localhost;Port=5433;Username=postgres;Password=postgres;Database=springaitest`). DB tables and seeds are created idempotently on startup.

## Gotchas

- **Identity header enforcement** (`Common/IdentityHeaders.cs`): provides `RequireTenant()` and `RequireUserId()` helper methods. `RequireTenant()` ensures `X-Tenant-Id` header is present and non-empty (missing → `400`); `RequireUserId()` ensures `X-User-Id` header is present and non-empty (missing → `400`). Controllers should call these explicitly where the identity is required — never duplicate this logic in handler code.
- **Correlation ID tracking** (`Common/CorrelationIdMiddleware`): Backend accepts an inbound `X-Correlation-Id` header from trusted upstream (Platform), validates it (exactly one value, 1–128 chars, trimmed, no control chars), and if valid, overwrites `HttpContext.TraceIdentifier` with it—otherwise silently falls back to the auto-generated TraceIdentifier (observability degradation is not a 4xx error). The middleware runs earliest in the pipeline (before `InternalTokenMiddleware`), so all downstream handlers and outbound calls to workflow use the validated ID. All outbound `HttpClient` calls to workflow automatically forward the current TraceIdentifier via `CorrelationIdForwardingHandler` in the `X-Correlation-Id` header. Error responses include `X-Correlation-Id` response header (matching ApiError body's correlationId). See [docs/cross-service-contracts.md](../docs/cross-service-contracts.md) "Error shape & correlation" for full chain semantics.
- **appdb owns ALL persistent data** (users, tenants, conversations, documents, vectors, config, skills) — restarts do **not** clear history. Only platform's in-memory short-term window resets. **rag_chunks vector search:** `rag_chunks` table has an HNSW index on the embedding column (`rag_chunks_embedding_hnsw_idx` using `vector_cosine_ops`) for ANN; requires pgvector ≥ 0.5. **Chunk writes:** inserted as a single multi-line `INSERT ... VALUES (...), (...), ...` statement per batch (reprocessing is idempotent via DELETE-then-INSERT inside one transaction), avoiding N round-trips.
- **Conversation history returns replies only** (`Conversations/ConversationDtos.cs`): the row stores both sides (`ConversationCreateRequest` carries `Prompt` and `Reply`), but `ConversationItem` projects `{Id, Reply, CreatedAt}` — the user's prompt is persisted and never read back. Clients therefore cannot rebuild a full transcript from history alone; the frontend reconstructs its own view from local state. Adding `Prompt` to the projection is the fix if full-transcript replay is ever required (a contract change: both the array and keyset-paginated endpoints, plus Platform's `/api/chat/history*` proxy).
- **Agent Registry storage** (`Agents/` feature folder): five tables — `agent` (draft + canonical bytes/SHA), `agent_revision` (immutable published revisions), `agent_revision_skill` (skill pins), `workflow`, `workflow_revision`. Draft/revision reads verify fixed-time SHA, no-BOM UTF-8, and canonical form (legacy rows missing canonical bytes fail closed). Draft mutation uses `If-Match` optimistic locking (409 stale, 428 missing). Publish locks all referenced revisions in one transaction; catalog-only Skills are not bindable (no immutable backend revision). Soft-disable preserves audit visibility; runtime separately requires enabled+published. System default Agent-Runtime Workflow (rev1, explicit start/end) is bootstrap-validated and reconciled on startup.
- **D4 Workflow/Orchestrator persistence** (`Workflows/`, `Orchestrators/`): Backend owns drafts/ETags/revisions/canonical bytes/reference locking; Workflow remains compiler authority (contract `d4-graph-ir-1`; unknown/legacy contracts fail closed). Orchestrator publish revalidates context tools against Workflow `/tools` risk metadata (`read`/`low` only), locks referenced revisions, and verifies Verifier Agent's `runtime_workflow` reference to a tenant-visible published `agent-runtime` harness. Both repository implementations must preserve the same preflight behavior.
- **Artifact storage and dual-track contract:** `skill`/`skill_revision` shared store; `kind` is trusted discriminator (`kind='agentic'` = Agent Skill, `kind='flow'` = Business Workflow). P2–P5 expose same row through both `/api/skills*` and `/api/business-workflows*`. Revisions/restore remain Skill-only (historical rows may mix kinds). Do not split tables or rewrite revision pins.
- **Business Workflow writes and export:** `/api/business-workflows*` owns flow CRUD and validates against workflow engine (502 on unreachable = syntax authority). `POST /skills/validate` is compatibility alias (retirement needs separate gate). Old `/api/skills*` flow routes remain during P2–P5; P5 may retire them (return `410` on flow writes) only after C8 proves new-route cutover, zero flow-write usage, rollback completion, and sign-off.
- **Document consumer** (`DocumentConsumerService` + `DocumentProcessor`): consumes `documents.process` (prefetch 1, manual ack, idempotent redelivery); chunk → embed → pgvector, then status `ready`/`failed`. Startup logs retrying `BrokerUnreachableException` until broker is up — expected noise (backed-off retry by design). Failure classification: transient (DB/timeout/embedding blips) → retry (max 3), terminal → mark failed; never ACK away failures. Retryable outcomes republish with `x-retry-count`; terminal/poison → manual copy to `documents.process.dlq` before ACK. DLQ is sibling queue (not native dead-letter exchange) to avoid `PRECONDITION_FAILED` on existing `documents.process` queue. Each message's whole handling (including retry/DLQ branches) runs inside a logging scope carrying the correlationId resolved from the body field, falling back to AMQP `CorrelationId`, bounded by the same rules as the `X-Correlation-Id` header; a message without one still processes normally. Terminal failures record a `failure_reason` from the closed `DocumentFailureReasons` set (never exception text — the column is returned to browsers) and reprocessing to `ready` clears it. Readiness reports the consumer's broker connection as a **non-required** `document_consumer` component, present only in processes that actually started the consumer — visibility, not gating (a broker blip must not get backend restarted).
- **Bounded built-in telemetry:** document-processing, database-readiness, and authoritative public artifact CRUD/read metrics are best effort (instrument listeners must not alter core behavior) and carry only fixed outcome/status enums—never artifact/document, tenant, or user IDs, content, or exception text. Artifact compatibility counts also emit the fixed-schema JSON line consumed by the P3-R2 stdlib exporter; this is only an input to [P3-R2 evidence](../plans/architecture-hard-reset/09-p3-r2-runtime-evidence-contract.md), not C8 approval.
- **Embeddings:** `EMBEDDINGS_PROVIDER` is `fake` (deterministic, default — tests and E2E rely on it) or `openai` (routed through LiteLLM, needs `text-embedding-3-small` in `litellm-config.yaml`).
- **Seed data** (from `DbBootstrap`): tenants `demo-a`/`demo-b` (invite codes `demo-a-invite`/`demo-b-invite`); users `admin-a` (ADMIN, demo-a), `user-a` (USER, demo-a), `user-b` (USER, demo-b); password `password123`. In lite mode (`DB_PROVIDER=inmemory`), the same seed data is hardcoded into `InMemoryAuthRepository` with matching BCrypt hashes.
- **App configuration (app_config table):** tenant-scoped `(tenant_id, key)` composite key; no shared global defaults. `GET /PUT /api/config/*` are `[AdminOnly]` + `RequireTenant()`-gated (`[AdminOnly]` is authorization filter running first: non-ADMIN without tenant header gets 403, not 400). `GET /api/config/runtime/{key}` is not ADMIN-gated (server-to-server), restricted to allowlist (currently `prompt.manifest_revision`). Migration from pre-tenant schema: atomically backfills old rows to all tenants, tightens schema to `NOT NULL tenant_id`, all in advisory lock. Rolling back to pre-tenant image leaks config and breaks INSERT. **Never roll back this migration.** Dapper/in-memory both enforce isolation; new tenants start empty (frontend provides programmatic defaults).
- **InMemory repositories (lite-only, DB_PROVIDER=inmemory):** singleton implementations in **three locations** — `src/Backend.Api/Data/InMemory/`, feature-folder-paired, and Dapper-colocated. When changing any repository, grep all implementations; `Data/InMemory/` is not the complete set. `DbBootstrap` skipped; tests use same fakes via global using `Backend.Api.Data.InMemory`, ensuring parity.
- **Dapper ↔ InMemory parity is not automatic:** the two implementations are **deliberately independent**, so drift is invisible — lite/tests can be all-green while production behaves differently, or vice versa. When changing either side, diff the other side's: state-set filter conditions, ordering, tenant filtering, null vs. empty collection, ETag/version increment, atomicity/transaction scope, cascade integrity. Regression tests for this class of drift must assert **authoritative state** (the underlying real record), never a local mirror/cache field — a mirrored field can stay "correct" even while the underlying bug fires. Real cases: `CancelAsync`'s child-run cascade missed the `waiting_input` status; `Expire()` never cascaded to the underlying `agent_run` at all; D7 evidence writes were a two-lock check-then-act in InMemory versus a single `FOR UPDATE` transaction in Dapper. Partial-failure semantics must match Dapper's transaction semantics: Dapper's multi-statement transactions are all-or-nothing (failure rolls back, next attempt is a clean retry); if InMemory instead commits a terminal state after a partial failure, the early-exit guard on that state permanently skips retrying the record.
- **Auth feature is the sole JWT signer:** it loads one P-256 private PEM from `JWT_PRIVATE_KEY_PEM_BASE64`, signs ES256 with exact `JWT_ISSUER`, `JWT_AUDIENCE`, and `JWT_ACTIVE_KID`, and issues 24-hour tokens with optional repeated `capabilities` claims. Platform receives only the matching public-key ring. Rotate by publishing the new public key to platform first, then atomically switching backend's kid/private-key pair; retain the previous public key for more than 24 hours plus rollout margin. Grants are persisted per user in `users.capabilities text[]` (default empty); role ADMIN does not imply `workflow.manage`. The demo `admin-a` user is explicitly granted it in both Dapper seed and in-memory seed. Claims are omitted when empty.
- **Credential timing and input bounds:** login always performs one BCrypt verification; unknown users verify against a precomputed dummy hash before returning the same 401 as a wrong password. Login/register identity fields are bounded to 128 characters on both proxy and backend contracts, while platform rejects auth bodies above 16 KiB before forwarding.
- **Agent Registry endpoints** are Builder management APIs: the entire `/api/agents*` controller requires `X-Internal-Token`, identity headers, tenant scoping, and ADMIN. There is deliberately no USER-readable draft endpoint; a future USER catalog must be a separate published-only, audience-filtered, redacted contract. All responses snake_case.
- **D3 caller grants (contract v1):** capabilities `tool.use:<toolName>` and `knowledge.read:<canonical-UUID>` are persisted; Platform forwards nonblank claims in `X-User-Capabilities`; Backend intersects with published `allowed_tools`/`knowledge_sources`. ADMIN implies nothing; malformed/wildcard fail closed. Scoped retrieval: `POST /api/retrieval/search` with `scope_contract_version:1` + server-injected sources; empty scope returns empty. Omitting both scope fields is reserved for legacy non-Agent workflows.
- **D3 audience groups:** tenant-scoped in `user_group_membership`, signed as repeated `groups` JWT claims, forwarded as `X-User-Groups`. Whole set fails on malformed input. Agent audiences: `role:ADMIN`, `role:USER`, or `group:<id>` only. Old bare `ADMIN`/`USER` read compatibly; old drafts must be edited to `group:<id>` before publish.
- **D3 run recovery:** dispatch ACK and execution recovery separate states. Expired unACKed claims recoverable; unACKed cancel prioritized over active lease. Lease generation prevents stale lease reopen; 30-second no-lease grace covers crash-before-claim. `waiting_input` requires durable `checkpoint_ref` + strictly-advanced version; resume rejects legacy/corrupt rows. Resume pinned to exact interrupt identity; later checkpoints continue without reinject.
- **D5 Root/child runtime:** `orchestrator_run` stores canonical snapshot bytes/hash + server-owned `root_input {message, observed_at}`; caller context never part of recoverable input. Root start claimed by Workflow, not Platform. `dispatch/complete` only ACK; retains fenced lease for transitions. Lease renew via `/commands/{command}/lease/renew` CAS-extends expiry. Child creation: atomically ledger + D3 run + command; snapshot `execution_kind` `orchestrator-worker` or `orchestrator-verifier` enforced by Workflow. Child terminal cascades to root; root cancel cascades. Context acquire returns `ready:false` when no read-only adapter (never caller-invented). `POST /api/admin/orchestrators/{id}/runs` rejects `message` >16384 chars with `413`.
- **D6 chat resolution:** `AGENT_CHAT_ENABLED` defaults false. Internal chat resolution uses the authenticated tenant/user and optional requested Orchestrator, returning either a pinned published Root snapshot or explicit `legacy`; it never trusts wire identity. Default routing requires an enabled tenant runtime binding and canary membership. Explicit unavailable or unauthorized selections fail closed. Chat-run allocation reuses D5 durability, idempotency, active-conversation uniqueness, commands, events, and immutable revision pins.
- **Context Enrichment (E1/E3):** `CONTEXT_ENRICHMENT_ENABLED` is independently fail-closed but effective only with D5 (`MULTI_AGENT_DISPATCH_ENABLED`). When off, `/api/contexts`, `/api/context-views`, `/api/context-policies`, and child `context-requests` routes return `404`; D5 `context/acquire` retains its established fail-closed not-ready result. `context_revision`, evidence, views, active policy, and source catalogue are Backend-owned canonical records. Child requests and append-only deltas are task-local: derive the worker/verifier view from the immutable child kind, pin the selected source/adapter and evidence provenance, and never replace the root's latest ready revision. A delta writes its revision, request compare-and-swap version, delta record, and redacted root event in one transaction. See [context-enrichment-contracts.md](../docs/context-enrichment-contracts.md).
- **D7 approval/effect authority:** Backend owns `agent_run_approval`, effect, evidence, outbox; Workflow consumes only internal resources under exact tenant/action/checkpoint/lease. `GET /api/runs/{run}/approvals` allows authenticated business approver without `workflow.manage` (decision rechecks tenant/role/expiry/state/duties). Effect identity once-only + atomic evidence/outbox prevent duplicates. `/api/admin/operations` requires `workflow.manage`; failed regression blocks rollout (unless audited override). Release retains immutable snapshots, returns redacted observability.
- **O5 one-shot triggers:** `AGENT_TRIGGERS_ENABLED` (default false, 404 fail-closed) gates `/api/admin/triggers*` (CRUD + occurrence history). Triggers feature folder owns `agent_trigger` and `agent_trigger_occurrence` tables, fire ledger, claim/lease mechanics, and BackgroundService polling. Fire creates D5 root runs via immutable execution principal snapshot (principal captured at trigger creation, not at fire time). Target Orchestrator and input mapping are pinned at creation; misfire marked if due occurrence not claimed within `misfire_window_seconds`. At-most-once: reclaimed occurrence returns existing root run ID. DTO whitelist: principal snapshot summary only, lease/fencing tokens omitted. No webhook sources, recurring cron, or in-place reschedule (cancel + recreate). See [docs/cross-service-contracts.md § O5](../docs/cross-service-contracts.md#o5-one-shot-durable-triggers).
- **Operations governance extensions:** `RUN_EVIDENCE_ENABLED` (E1, default false) adds `operations_run_evidence` (append-only, validated before metric write); lineage/SHAs server-resolved (never trusted from caller). `GET /api/admin/operations/evidence-reconcile` proves the two ledgers never diverge. `RUN_EVAL_ENABLED` (E2/E3) adds `eval_suite`/`eval_run`/`eval_case_result`; POST idempotency checked before runner; regressions gate recomputes `passed` from policy/results (fail-closed on empty policy or FAIL/ERROR). `PROMPT_ARTIFACTS_ENABLED` (P1) adds `prompt_component_revision`/`prompt_manifest_revision` (immutable, content-addressed); published Agent may pin `prompt_manifest_{revision,sha256}`. `GET /api/prompt-manifests/{revision}/resolved` is sole content route, server-to-server only, never proxied to browsers. D3/D5 `execution_snapshot` embeds optional `agent.prompt_manifest` (absent when unpinned); D5 root snapshot (`BuildOrchestratorRoot`) has no `agent` key at all and never carries prompt manifest pin. Pre-P1 snapshots unchanged.
- **Never expose to LAN:** the service binds `127.0.0.1` only and *trusts* the `X-Tenant-Id`/`X-User-Id`/`X-User-Role` headers after `X-Internal-Token` passes. Its security model assumes only platform and workflow can reach it.
- **Credential startup gate:** outside `Development`, startup rejects blank or committed-development database, internal-token, RabbitMQ, issuer/audience, kid, or private-key values. Backend must never distribute its private key; only derived public PEMs belong in platform's verification ring.
- **Env:** `DB_CONNECTION_STRING`, `INTERNAL_API_TOKEN` (development default `internal-dev-token`), `JWT_ISSUER`, `JWT_AUDIENCE`, `JWT_ACTIVE_KID`, `JWT_PRIVATE_KEY_PEM_BASE64`, `EMBEDDINGS_PROVIDER` (default `fake`), `EMBEDDING_MODEL` (default `text-embedding-3-small`, used only when `EMBEDDINGS_PROVIDER=openai`), `LLM_BASE_URL` (default `http://localhost:4000`) and `LITELLM_KEY` (default `sk-1234`) — the LiteLLM endpoint/virtual key for embeddings, also read only when `EMBEDDINGS_PROVIDER=openai`, `RABBITMQ_URL`, `WORKFLOW_BASE_URL` (e.g. `http://localhost:8001`, used for skill validation at write time), `DEPLOYMENT_VERSION` (default `unknown`) — stamped onto the P3-R2 artifact-compatibility JSON evidence line only, never behavior. Feature flags, all default false and fail-closed: `WORKFLOW_DESIGNER_ENABLED` (D4 authoring routes only — deliberately excluded from runtime readiness so turning the designer off never stops dispatch), `MULTI_AGENT_DISPATCH_ENABLED` (D5), `AGENT_CHAT_ENABLED` (D6; effective only when `MULTI_AGENT_DISPATCH_ENABLED` is also true), `CONTEXT_ENRICHMENT_ENABLED` (E1/E3; likewise requires `MULTI_AGENT_DISPATCH_ENABLED`), `AGENT_WRITE_TOOLS_ENABLED` (D7), `AGENT_TRIGGERS_ENABLED` (O5), `RUN_EVIDENCE_ENABLED`, `RUN_EVAL_ENABLED`, `PROMPT_ARTIFACTS_ENABLED` (these last four independently fail-closed, gating no other flag). **Lite-only:** `DB_PROVIDER` (unset or `dapper` = Npgsql + DbBootstrap, `inmemory` = in-memory repositories with seed accounts, skips DbBootstrap and Npgsql connection pool — placement conventions above).

## Testing

xUnit with hand-written fakes (no mocking library). Coverage spans Auth (registration, JWT signing), Retrieval (vector search), Config (ADMIN perms, tenant-scoped), chunking, fake-embedding determinism, and internal-token validation.
