Solution-wide guidance only. Each area has its own `AGENTS.md` (+ `CLAUDE.md` importing it) with layout, commands, and area-specific gotchas — **read the area file before working in that area**; Claude Code loads it on demand when files there are touched.

## Subagent Delegation

**Delegate by default — do not wait to be asked.** Route substantive work to the project subagents in `.claude/agents/` and run independent ones in parallel; the main agent orchestrates (write the spec, delegate, integrate results):

| Agent                  | Use for                                                                             |
| ---------------------- | ----------------------------------------------------------------------------------- |
| `dotnet-implementer`   | Any implementation in `platform/` or `backend/` (+ xUnit tests)                     |
| `frontend-implementer` | Any implementation in `frontend/`                                                   |
| `python-implementer`   | Any implementation in `workflow/` (nodes, engine, skill compiler, sandbox + pytest) |
| `code-reviewer`        | Review after every non-trivial change, before declaring done                        |
| `code-simplifier`      | Simplify/refine recently changed code (clarity, reuse, dead flexibility) — behavior-preserving, after review |
| `e2e-verifier`         | Full-chain verification via docker compose when cross-service behavior changed      |
| `docs-updater`         | Sync README/AGENTS/docs files after feature or architecture changes                 |

Only trivial work (typo-level edits, quick Q&A) stays in the main loop.

**Every subagent definition must pin all four knobs in its frontmatter:** `model`, `tools`, `hooks`, and MCP access (MCP tools are granted as `mcp__<server>__<tool>` entries inside `tools`). Where one is deliberately absent (e.g. no hooks for a docs-only agent), record that as a YAML comment in the frontmatter — omission must be a decision, never an oversight. New agents follow the same rule.

**Spot-check subagent completion reports, especially three claim types**: (a) lock/concurrency structure ("this ordering is safe"), (b) dead code ("nothing calls this"), (c) artifact/workspace state ("temp files deleted", "workspace clean") — verify with grep/Read yourself, don't take the report at face value (real cases: a claimed-clean workspace still had two temp files on disk; two agents signed off a lock ordering that held an ABBA deadlock caught only by code review). Conversely, a spec's blanket hard rule may not fit the file at hand (an agent rightly refused "never call across repositories while holding a lock" after showing the file's existing methods all did so with no ABBA) — give rules the specific risk they guard against so the agent can judge applicability instead of following blindly.

## Cross-Service Contracts

These facts span two or more areas — changing one side silently breaks the other — so they live here as **invariants only**, not in the area files. Full contracts live in [docs/cross-service-contracts.md](docs/cross-service-contracts.md) — **read the relevant section there before changing any side of these**:

- **Public chat API** (platform; P4-1 PARTIAL): every `/api/chat*` route requires JWT — `ChatController` carries a class-level `[Authorize]`; anonymous chat, anonymous history, and anonymous short-term continuity no longer exist. Identity, mem0 grouping, and persistence derive from JWT `{tenant}:{user}`; wire-level `userId` is removed. Missing/blank `conversationId` → Platform generates a canonical UUID and returns it in `X-Conversation-Id` (`turnId` not yet delivered).
- **Two SSE formats, both deliberate:** `/api/chat/stream` writes hand-rolled `data:<value>` (no space); the AG-UI endpoint `/api/copilot/agui` writes protocol-standard `data: ` (with space). Every proxy hop (Vite dev proxy, frontend nginx) must keep `proxy_buffering off` on SSE paths. Mid-stream failure: platform writes an `event:error` frame, then ends the response normally.
- **AG-UI copilot:** the browser connects **directly** to platform's `/api/copilot/agui` — POC posture, no Node bridge. The endpoint **requires authentication** and fails closed when the JWT lacks a nonblank tenant/user claim; session isolation is `{tenant}:{user}` from JWT claims, never wire data. It shares the same skill-routing/mem0/persistence core as `/api/chat*` — different personas/transports, not different brains.
- **Error shape & correlation:** every API returns ApiError `{timestamp, status, code, message, correlationId, fieldErrors}` (camelCase; `code` is stable machine-readable). Platform is the correlationId authority: it derives the ID from its own `HttpContext.TraceIdentifier` (never trusts inbound values) and forwards it via `X-Correlation-Id` to backend and workflow; error responses return the same ID in the `X-Correlation-Id` response header. Response field naming is mixed **by design** (documents/workflows/analysis snake_case; auth/config camelCase) — do not "fix" either side.
- **Backend trust boundary:** backend (`:8002`) globally requires `X-Internal-Token: <INTERNAL_API_TOKEN>` on everything except `/health` (one middleware, `InternalTokenMiddleware`). Identity headers (`X-Tenant-Id`, `X-User-Id`, `X-User-Role`) are **not** gated by that same middleware — enforcement is per-endpoint: handlers that need tenant scoping call `RequireTenant()` themselves (missing `X-Tenant-Id` → `400`), while `X-User-Id`/`X-User-Role` stay optional by default (no header → empty/null) — except identity-requiring endpoints (D3/D7 runs, approvals, and config management) which call `RequireUserId()` or `RequireTenant()` as required (missing → `400`). `/api/config` (`GET` and `PUT`) are ADMIN-only and tenant-scoped: both require `[AdminOnly]` authorization filter (non-ADMIN → 403) and `RequireTenant()` identity check (missing `X-Tenant-Id` → 400); values are per-tenant (each tenant has its own isolated key–value store, shared defaults do not exist). Config values are ADMIN-authored content (e.g. `agent.defaults.system_prompt`), never USER-readable. Only platform and workflow call it; workflow (`:8001`) shares the same trust model. Both bind `127.0.0.1` and must never face LAN or public internet.
- **Async document processing:** platform publishes to RabbitMQ queue `documents.process` and returns `202 {id, title, status:"processing"}`; backend's consumer chunks/embeds/stores and flips status to `ready`/`failed`. The document is absent from `GET /api/documents` until consumed — eventual consistency by design (frontend bridges the gap with optimistic insert + polling). Broker unreachable at publish time → `502`.
- **Auth:** backend is the sole JWT signer (ES256, one P-256 private key selected by the active kid); platform receives only the public verification ring, binds tokens to an exact `iss`/`aud`/`kid`, and does not try unrelated keys when `kid` is unknown. Key rotation is ordered: deploy a ring containing both public keys, atomically switch backend's active kid and matching private key, retain the old public key for **more than the 24-hour token lifetime** (plus rollout margin), then remove it — issuer/audience stay stable during key-only rotation. Any `401` while logged in, including AG-UI, clears the session and returns to login.
- **Two memory layers, don't confuse them:** *short-term* = Microsoft Agent Framework session store, shared by both platform hosted agents; resets on restart. Isolation still differs by chain pending P4-3: AG-UI uses `withIsolation:true` keyed on nonblank JWT `{tenant}:{user}` (fail-closed), while `/api/chat*` prefixes its canonical conversation UUID with authenticated `{tenant}:{user}` at the derivation layer. *long-term* = mem0 (cross-session facts), grouped by JWT `{tenant}:{user}` and covering both chains. Best-effort is a shared pipeline boundary: every `IMem0Client` failure is logged and degrades (`recall` → empty, `remember` → no-op). Everything else persists in appdb across restarts.
- **Skill concepts and engine boundary (P0–P5):** an **Agent Skill** is a portable Anthropic-style `SKILL.md` package, not a YAML flow; a **Business Workflow** is the declarative YAML flow compiled by the **Skill Engine** (`workflow/app/engine/`); both share the physical `skill`/`skill_revision` tables behind the trusted `kind` discriminator. A **Harness** is the fixed runtime LangGraph (`workflow/app/runtime/graph.py`); its D4 Graph IR declaration is a **Harness Workflow**, not a Business Workflow or executable graph. `/api/skills*` + `/api/business-workflows*` dual-track is deliberate during P2–P5: P5 may make public `/api/skills*` Agent-Skill-only **only after** C8 proves Business Workflow traffic cutover, legacy flow-write usage `= 0`, and an ended rollback window — and the internal `/skills/validate` alias retires only through its own separate consumer/usage/rollback gate.
- **P3-R2 compatibility evidence:** `artifact_compatibility_usage_total` uses only bounded dimensions; Platform replaces public invoke origin with a server-derived value, and Workflow is the sole unified-invoke counting authority. Instrumentation/export code alone is not C8 evidence. Details: [P3-R2 runtime evidence contract](plans/architecture-hard-reset/09-p3-r2-runtime-evidence-contract.md).
- **Prompt manifest (P1):** Backend's `GET /api/prompt-manifests/{revision}/resolved` returns raw pinned prompt composition, internal-only — never proxied to browsers or UI tools. Pinned-run manifest unavailability fails closed in workflow (`prompt_manifest_unavailable`); platform's five-slot composition instead falls back to constants on any failure. Both sides: `PROMPT_ARTIFACTS_ENABLED`/`PROMPT_ARTIFACTS_SHADOW` default false; shadow mode is observe-only (constants + warning, no pins accepted).
- **Eval framework (E2):** Backend owns durable eval suite/revision/run/result authority; platform's eval proxy routes under `/api/admin/operations` share D7's `AGENT_WRITE_TOOLS_ENABLED` pre-auth 404 gate, while `RUN_EVAL_ENABLED` governs only the backend/workflow side. Workflow's internal `/evals/run` executes a Backend-supplied versioned suite deterministically, is stateless for eval, persists nothing, and is gated by `RUN_EVAL_ENABLED` (fail-closed 404). Backend's regression gate recomputes `passed` server-side from stored suite policy and case results — never trusts the caller.
- **Feature-gate 404s are indistinguishable from route-not-found:** whenever a flag is off, Platform and Backend answer with the same 404 body that service uses for any unknown route — never a "feature disabled" style message — so probing cannot tell a gated route from a nonexistent one. Do not reintroduce a gate-specific message or code.

### Agent platform (D1–D7) — invariants only

Full contracts live in [docs/agent-platform-contracts.md](docs/agent-platform-contracts.md) — **read the relevant section there before changing any side of these**:

- **Agent Registry (D1):** `/api/agents*` is an ADMIN-only Builder API (platform → backend proxy) behind `AGENT_BUILDER_ENABLED` (default false, 404 fail-closed before auth). Never reuse it as a USER catalog. If-Match/ETag optimistic locking; ADMIN does not imply `workflow.manage`.
- **Business Rules (D2):** Agent `business_rules` is a canonical JSON AST (`version:1`), never code or prompt text. Workflow owns catalog/validator/three-valued evaluator; unknown facts resolve through explicit `onUnknown` (default deny), never silent false.
- **Direct Agent runtime (D3):** ADMIN-only test runs of immutable published snapshots behind fail-closed `AGENT_TEST_RUN_ENABLED`. Backend owns durable run/command/lease state; Workflow owns LangGraph execution + PostgreSQL checkpoints. No streaming, approvals, or write tools in this phase.
- **Workflow Designer & Orchestrator Registry (D4):** gated by `WORKFLOW_DESIGNER_ENABLED` + exact `workflow.manage` capability (ADMIN alone insufficient; disabled → 404 before auth). Workflow is the sole Graph IR compiler/validator; Backend owns drafts/revisions/ETags/locking; root context tools permit only `read`/`low` risk, all else fails closed.
- **Root Orchestrator runtime (D5):** `MULTI_AGENT_DISPATCH_ENABLED` fail-closed, default false. Backend owns immutable snapshots, command claim/renew/generation fencing, budgets, cascade cancel; Workflow claims only Backend-issued artifacts and enforces verifier independence, token caps, PASS-only aggregation. Public events are server-redacted.
- **Context Enrichment (E1/E3):** `CONTEXT_ENRICHMENT_ENABLED` is independently fail-closed but effective only with D5. Backend owns canonical, policy-evaluated context revisions, evidence, role views, task-local child context requests, and their transactional event history; Workflow may submit content only, never identity, ownership, task lineage, or role. E1/E3 routes are hidden with `404` while off (D5 context acquire keeps its existing not-ready contract). Read [docs/context-enrichment-contracts.md](docs/context-enrichment-contracts.md) before changing either side.
- **Agent Chat canary (D6):** Platform's `AGENT_CHAT_ENABLED` + `AGENT_CHAT_TENANT_ALLOWLIST` controls public canary selection. Backend's effective chat-runtime gate additionally requires D5; Workflow has no separate public chat-dispatch flag or endpoint. Ineligible callers stay on the legacy shared-core chat path; an explicitly requested unavailable Orchestrator fails closed, never falls back. Rollback is configuration-only.
- **Write tools & approvals (D7):** `AGENT_WRITE_TOOLS_ENABLED` fail-closed in all three services; only write tool is tenant-allowlisted `runtime.write_evidence`. Durable `waiting_approval` before any effect; once-only effect identity + atomic evidence/outbox make replay safe. `/api/admin/operations` requires exact `workflow.manage`.

## Coding Style

All development agents follow the constitution in [docs/coding-standards.md](docs/coding-standards.md): Karpathy's four principles, reuse-first, Node-First for `workflow/`, Business Rules live only in Backend, test value over test count, and **every plan must inventory old code that the new requirement turns into dead or duplicated code**. Semantic code search goes through the codebase-memory MCP; Grep is for literal strings.

Match the surrounding code's naming, structure, and idiom. Two deliberate choices you can't infer from a single file: both .NET test suites use **hand-written fakes, no mocking library**; the frontend has **no router and no UI library** by choice — do not add dependencies without explicit authorization.

## Commit & Pull Request Guidelines

Short imperative commit subjects. PRs: summary, test commands run, screenshots for UI changes, and call out any `infra/` configuration edits. Repository CI is `.github/workflows/ci.yml` (backend/platform/workflow/frontend test suites + compose expansion/hardening/resource-calibration validation + container-hardening verification + full-chain-smoke; backend job requires pgvector service container).

## Security & Configuration Tips

Do not commit secrets. Copy `infra/.env.example` to `infra/.env`; it contains public **Development-only** defaults, including the ES256 development key pair. The real `OPENAI_API_KEY` lives only there, behind LiteLLM. All services talk to OpenAI-compatible models **through LiteLLM** (`http://localhost:4000`, env `LLM_BASE_URL`, virtual key `sk-1234`), never directly; provider/model routing belongs in `infra/litellm-config.yaml`. The chat model comes from env `CHAT_MODEL` (default `gpt-4o-mini`; override to `mock-gpt` to test without quota). Per-service env variables are listed in each area's AGENTS.md. Treat prompt/completion logging and Langfuse traces as sensitive outside Development. Platform, Backend, and Workflow fail startup outside Development when required credentials are blank or still equal committed development values; production deployments must provide separate JWT signing/verification material, internal token, database/broker credentials, and runtime HMAC material where enabled. The local start/evidence helpers explicitly opt into Development; raw Compose defaults application services to Production.

Line endings: all `*.sh` must stay LF — a CRLF shebang makes `./script.sh` fail with `not found` inside Linux build images; `.gitattributes` pins this.
