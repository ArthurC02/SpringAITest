# Frontend SPA (React 19 + Vite + TypeScript, `:5173`)

Area-specific guidance. Cross-service contracts (SSE formats, ApiError shape, snake/camel field naming, 202 flow, auth) live as invariants in the repo-root [AGENTS.md](../AGENTS.md) with full detail in [docs/cross-service-contracts.md](../docs/cross-service-contracts.md) — the API contract is defined by platform's actual responses, never invent fields.

## Layout

- `src/api/` — one module per backend feature; `http.ts` owns `apiFetch` (Bearer injection, ApiError parsing, global 401 logout) and `apiFetchWithEtag` (ETag-aware CRUD wrapper for optimistic locking).
- `src/hooks/` — `useAuth`, `useChat`, `useDocuments`, `useResource` (shared read-only load state machine: data/loading/error/reload).
- `src/components/` — one component per view plus shared primitives; `AppShell` owns sidebar + view switching + CopilotKit readables/actions. IA decisions you can't infer from the tree: `ConfigView` hosts four peer tabs (`businessWorkflows`/`agentSkills`/`nodeParams`/`general`); **`AgentPlatformView`** is the single "Agent 平台" sidebar entry — it owns the one `.view` wrapper and switches three inner tabs (**`AgentsView`**, **`WorkflowsView`**, **`OrchestratorsView`**) which render tab bodies only, never their own `.view`/`.view__head`; **`AgentBuilderCopilot`** is headless (rendered by `AgentEditor` only when `sub === 'edit'`, returns null); **`ApprovalInbox`** (D7 approvals) is gated by `agentWriteToolsEnabled`; **`OperationsGovernanceView`** (release cockpit with `EvaluationPanel` eval drill-down) is gated by `agentWriteToolsEnabled && canManageWorkflow`; **`RunsView`** (執行總覽, O2) is gated by `runDiscoveryEnabled && workflow.manage`; **`TriggersView`** (排程觸發, O5 one-shot durable triggers) is gated by `agentTriggersEnabled && workflow.manage`.
- `src/workflowDesigner/` — React Flow projection/UI only: `graphAdapter` keeps semantic Graph IR separate from `ui_metadata`; `connection` performs catalog-driven immediate typed-port checks; `layout` uses ELK but emits positions only; `WorkflowDesigner` owns palette/canvas/inspector/simulated-trace display. `history` (undo/redo reducer + `useDraftHistory`), `clipboard` (cut/copy/duplicate/paste with semantic filters), `keyboard` (scope-guarded shortcuts via `isTextEntryTarget`), `overlay` (`useOverlay` for focus/click-outside handling), `NodePicker` (catalog search + five entry points), `ContextMenu` (right-click menu), `WorkflowEdge` (custom Bézier + hover insert/delete toolbar), and `DesignerActionsContext` (actions bridge to subcomponents). It must never execute or canonicalize a workflow.
- `src/types.ts` (shared types), `src/agentBuilder.ts` (Agent draft normalization and fail-closed authoring helpers), `src/storageKeys.ts` (localStorage key constants), `src/format.ts` (utility: `fmtDate`). Dev proxy in `vite.config.ts`; container proxy in `nginx.conf` (SSE paths need `proxy_buffering off`; `.mjs` MIME mapping must be kept — pdf.js worker chunk, browser module MIME checks reject it without one).

## Commands (run from `frontend/`)

```bash
npm install
npm run dev     # Vite on :5173, proxies /api → :8080
npm run build   # tsc type-check + vite bundle
npm run lint    # oxlint
npm run test:unit # Vitest pure logic + Playwright mocked-browser regression tests
npm run test:unit:logic # Vitest only (fast, no browser/server)
npm run test:unit:ui # Playwright mocked-browser tests only
npm run test:evidence:install # install Chromium for release-evidence browser gates
npm run test:evidence         # full-compose Playwright gates (PW_BASE_URL defaults to :5173)
```

The normal frontend gate remains lint + build. `test:evidence` is a release gate only: it
expects an externally started full compose stack and never mocks AG-UI. Set `EVIDENCE_DIR`
to the ignored root artifact directory (for example `../artifacts/copilot-shared-core/<run-id>`
when running from `frontend/`). If Chromium or the evidence stream endpoint is absent, the
outer evidence harness must report `BLOCKED`; a Playwright skip is never release PASS —
`playwright.config.ts` registers `evidenceSkipGuardReporter.ts`, which fails the run itself
(non-zero exit) whenever any evidence test is skipped, so running `npm run test:evidence`
directly without the harness cannot report a false PASS either.

## Conventions & Gotchas

- Component files `PascalCase.tsx`, hooks `useX.ts`, React function components only. No react-router — view switching is `useState` in `AppShell`. No UI library — hand-written CSS on the custom properties in `index.css`. Do not add dependencies without explicit authorization — the two exceptions are `pdfjs-dist@6.2.108` and `mammoth@1.12.0` (exact pin, lazy-loaded, must never enter the main bundle).
- **Skill concept IA:** `AgentSkillHome` manages portable `SKILL.md` Agent Skill packages; `BusinessWorkflowHome` manages declarative YAML Business Workflows. They are peer Config tabs, not two filters in one ambiguous "Skill" home. `kind` from the API is the sole classification source—never inspect definitions or package text. `SkillRunPanel`, history, and trace remain shared because invoke stays unified. `NodeParamsTab` is a peer Harness configuration tab, not a flow-authoring editor; D4 Graph IR is a **Harness Workflow**, not a Business Workflow. P2–P5 dual-track route support does not authorize presenting P5 as complete: retain the legacy-compatible flow surface until backend C8 has approved its removal.
- **Design tokens & shared UX primitives:** semantic colors are tokens in `index.css` (`--danger/--success/--warning` + `-bg` tints, `--on-accent`) with dark-mode overrides — never hardcode `#dc2626`-style values; every text/background pair must meet WCAG AA 4.5:1 in both modes. Reuse the shared primitives instead of per-view one-offs: `Toast.tsx` (`useToast`, success feedback), `Skeleton.tsx` (first-load only — never on refresh of existing data, and loading must not render as "no data"), `ErrorBoundary.tsx` (wraps the view area, keyed by view). Animations/transitions must stay inside the `prefers-reduced-motion` guard; interactive elements rely on the global `:focus-visible` rule.
- **Chat scroll model:** three-state (anchored → auto-follow, scrolled-up → stop, "跳至最新" pill to re-anchor; sending a message force-re-anchors). Streaming appends must scroll with `behavior: 'auto'` — smooth scrolling races the `onScroll` near-bottom check and permanently disengages auto-follow; smooth is only for the user-initiated jump.
- **Every API call goes through `apiFetch`** — never hand-roll fetch with auth headers. Login stores `{token, username, role, tenantCode}` in localStorage; any 401 while logged in clears the session **and** the `springai-chat:*` keys (cross-user privacy on shared browsers), then returns to login with a dismissible "session expired" notice.
- **JWT storage in localStorage is an evaluated acceptance, not an oversight (W2-04):** accepted because first-party code has no known XSS hole (`react-markdown` doesn't render raw HTML by default; the one `dangerouslySetInnerHTML` use is hljs-escaped) plus CSP as defense-in-depth. Re-evaluate (migrate to httpOnly cookie) if any of: self-serve signup opens to untrusted users; a third-party frontend script is introduced or CSP must be relaxed for an integration; a formal security audit runs; an actual XSS is found. Full rationale: [plans/wave2-decisions-2026-08-10.md § W2-04](../plans/wave2-decisions-2026-08-10.md#w2-04-jwt-保管位置). **Chat state persistence:** `useChat` auto-saves to localStorage with 500ms debounce + forces a flush on component unmount and `beforeunload` to avoid message loss on tab close. Logout must invalidate the active persistence generation before clearing storage so delayed debounce/unmount flushes cannot restore the previous user's messages.
- **Chat SSE (P4-1 PARTIAL):** parse `data:` + `event:` (no space) via `fetch` + `ReadableStream`. `event:error` = mid-stream failure (platform sends terminal frame, client preserves partial content). No `userId`; `conversationId` optional (Platform returns canonical UUID in `X-Conversation-Id`). "New conversation" clears key for new allocation. Errors caught in `streamChat()`, thrown to `useChat`, shown as error bubble with partial content.
- **Documents 202 flow:** optimistically insert a `processing` row, poll `GET /api/documents` every 2s (60s cap). The poll merge uses `useDocuments`' `pendingRef` pattern — a full list replacement must never wipe the optimistic row before the server catches up (eventual consistency).
- **CopilotKit sidebar:** `@copilotkit/react-*` pinned EXACT (1.62.3); `@ag-ui/client` to react-core's internal version (0.0.57) — mismatch causes type errors. `App.tsx` uses `new HttpAgent({url: '/api/copilot/agui'})` + `agents__unsafe_dev_only` (POC; production needs Node bridge). Endpoint requires auth. `HttpAgent` built in `useMemo` keyed on `session.token`, sends `Authorization: Bearer`; custom fetch must route `401` to global logout (clear session + chat keys, return login). Always rebuild on login/logout/account switch.
- **CopilotKit safety rules:** NEVER put `session.token` in a `useCopilotReadable`. Actions run client-side through `apiFetch` so platform authorization stays the real boundary. `renderAndWaitForResponse` confirm buttons are bare React handlers — always try/catch and call `respond()` on both success and failure, or the LLM run hangs.
- **Agent Builder Copilot (副駕):** registered readables (draft summary, skill/tool catalog, business rules catalog, field vocabulary) and two actions (`fillAgentDraft`, `addAgentBusinessRule`). Invariants: modifies local form state only, never calls publish/draft-save/validate endpoints; drafts/rules/tools/skills are filtered against server catalogs (non-existent items discarded), missing specs exit silently without touching that field; list fields are replaced wholesale, not appended; Business Rules use existing `ruleBuilder` helpers (LLM only provides fact/operator/action IDs, never raw JSON AST); locked state (readonly/busy/ETag conflict) blocks all mutations; readables omit credentials and endpoints; copilot cannot write `audience` or `execution_roles`.
- ADMIN-only Config view is hidden by sidebar filtering; backend role enforcement is the real boundary (the UI check is UX, not security).
- **Agent Builder flag** (`agentBuilderEnabled` from `GET /api/features`): toggles the Agents **tab** inside the Agent 平台 workspace. When false, the tab is hidden and Platform returns 404 for `/api/agents*`; when true, it requires an ADMIN login. The sidebar entry itself appears when *any* tab is open, so each tab keeps its own fail-closed gate (`agentBuilderEnabled && ADMIN` vs `workflowDesignerEnabled && workflow.manage`); with one visible tab the tab bar is not rendered. The frontend fetches the flag once per app load, so changing the Platform environment value requires restarting Platform and reloading the browser.
- **Agent draft form layout:** basic section (always expanded: name, description, prompt, skills, knowledge, audience) + advanced section (collapsible: slug, roles, capabilities, output, tools, rules, limits). On advanced-field validation error, auto-expand details and map to root field (e.g., `runtime_limits.timeout_seconds` → `runtime_limits`).
- **Agent creation defaults:** `agentBuilder.ts` exports named constants (max_tool_rounds, max_context_rounds, timeout_seconds, token_budget, step_budget, system_prompt) and applies them on creation only — never overwrite an existing draft's values. Defaults are overridable by the authenticated tenant's `app_config` per-tenant `agent.defaults.*` keys; invalid values (non-integer, negative, missing) fall back to constants. `listConfig()` failures degrade silently (no error toast). Defaults are visible/editable in ConfigView's "一般設定" tab; each tenant manages its own overrides independently.
- **Agents workspace ETag handling:** every agent GET captures the ETag for draft update and validate. A 409 (stale ETag) shows a blocking conflict banner and disables the form/actions until reload fetches fresh data and a new ETag. If-Match is omitted from initial POST (creation).
- **D3 Agent test console:** ADMIN-only when both Builder + test-run flags enabled. Start reuses persisted idempotency key across retries/reloads; new key on accepted run or reset. Polls cursor-based events, preserves partial output/trace, supports exact waiting-input resume + durable cancel, shows cancelling state until terminal. Cleared by shared logout path.
- **D4 Workflow Designer:** requires `workflowDesignerEnabled` + exact `workflow.manage` (not ADMIN alone). `@xyflow/react` (12.11.2) + `elkjs` (0.12.0) pinned. Store Graph IR separate from `ui_metadata`; UI changes must never touch semantic definition or hash. Client type checks = UX only; server validates. Simulated overlays keyed by stable node ID, never write back to draft. **n8n interaction model:** left-drag-empty = marquee select; middle/space-drag = pan; scroll = pan; Ctrl+scroll = zoom; right-click = context menu. **History & positions:** undo/redo owned by `WorkflowEditor` (passed as `canUndo/canRedo/onUndo/onRedo` props); viewport-only changes excluded from history; position commits only when `dragging !== true` in `onNodesChange`. **Keyboard:** two-level scope guards—outside `.workflow-designer` = entirely pass-through (native Ctrl+C/A/Escape work); inside canvas, `isTextEntryTarget` blocks all shortcuts; Tab intercepted only when `event.target === canvasRef.current && !event.shiftKey`, Shift+Tab always passes (WCAG 2.1.2 No Keyboard Trap). **Delete fail-closed:** required nodes protected; **add fail-closed:** paste/duplicate silently drop `{requiredStage, type-already-exists}` pairs (matches workflow validator's `duplicate_required_stage`). Edge connects validated per-edge even in batch pastes.
- **D6 Orchestrator chat selector:** `agentChatEnabled` only permits attempting the authenticated, USER-safe `/api/chat/orchestrators` catalog. A control/non-allowlisted tenant receives 404 and must retain the exact legacy Chat UI. Canary users see `Default` plus eligible published redacted Orchestrators; selection adds optional `orchestratorId` to `/api/chat/stream` and rebuilds the AG-UI `HttpAgent` with the same `X-Orchestrator-Id`. Never consume admin Orchestrator DTOs or expose draft/audience/binding policy. Platform owns active-root resume/cancel on selection changes. Account/tenant changes clear selection before either transport can reuse it; SSE parsing and global 401 logout stay unchanged.
- **SkillRunPanel:** renders input fields by type — `str` fields use text input with min_length validation; `int`/`float` use `<input type="number">`; `bool` use checkbox; `list`/`dict` use JSON textareas (each non-string field has its own textarea, never collapsing the entire form to JSON). Empty optional fields are omitted from the request; invalid/missing required fields show field-level error messages in Chinese.
- **SimpleSkillEditor:** supports both create and edit modes. On create, auto-fills the form from the selected template skeleton. On edit, reads back the stored `simpleForm` state and re-fills the form; the template and skill name are locked. On save, recomposes the YAML definition from form values and updates `simpleForm`; dataflow warnings in the recomposed definition are shown as non-blocking notices to the user (distinct from blocking errors).
